# 2026-09-18a — Profiling and bit-exact speed-up of the MMWSpalling step

Context: the D2d campaign case R7_1mm (1 mm, 120×120×400, 4 ranks, dt 4 ms) was running at
0.245 s per step (56 wall-s per simulated s). Profiled two live ranks with macOS `sample`
(10 s each, non-intrusive). Build is -O3 -flto, MPI only.

## Where the step went (share of rank time)
| Item | rank 0 | rank 3 |
|---|---|---|
| AdvanceMicrostructure conduction kernel | ~45 % | ~45 % |
| of which `exp(-a_D·D)`, 7 calls per cell, a_D = 0 | ~12 % | ~11 % |
| `Table::Invert` bisection (InvertHtoT) | 14 % | 18 % |
| FillPatch of temp (ghost copy + `BC::Constant::FillBoundary` sweep) | 20–25 % | 20 % |
| MPI wait (load imbalance: surface work on top-z ranks) | 17 % | ~5 % |
| static-field `RealFillBoundary` every step | ~4 % | ~4 % |

## Code changes (all bit-identical by construction)
- `src/Numeric/Material/Table.H`: uniform-in-H seed table + forward walk replaces the 14-step
  bisection in `T_of_H`; same bracket, same interpolation formula.
- `src/Integrator/MMWSpalling.H`: skip `exp` when `kappa_damage_alpha == 0`; fill phase /
  grain_id / kappa ghost layers once per InitializeMicrostructure (flag `micro_ghost_filled`),
  D still every step; `BeamSource` returns 0 immediately when P == 0.
- `src/BC/Constant.cpp`: `FillBoundary` returns early when the grown box lies inside the
  domain (every kernel in it writes only out-of-domain cells).

## Verification (baseline = binary that was running the campaign, source unchanged since)
- 2 mm campaign config, 1 rank, 30 s (7500 steps, spallation from 3.2 s): thermo.dat (301 rows),
  removal_events.csv (8595 rows), jet_profile.csv, final plotfile: byte-identical.
- Same config, 4 ranks, 6 s: thermo, 617 removal rows, all 4 plotfile chunks byte-identical.
  (1-rank vs 4-rank differ only in ledger_err at 1e-16, identical for the baseline: pre-existing.)
- Unit tests PASS with the new binary: stefan, heterogeneous_enthalpy, heterogeneous_kappa,
  spall_event, beam, sp_melt_skeleton, beam_void_closure, convective_patch, robin_pinned (11/11,
  includes P4 == P identity).

## Levers not taken (user's call, change the pre-registered campaign)
- `DT_CAP = 4 ms` in run.py is the binding step limit: the 5 K overshoot rule allows 7 ms at 1 mm
  and 14 ms at 2 mm; explicit diffusion limit at 1 mm ≈ 0.24 s.
- Pencil boxes (`max_grid_size = 30 30 400`) would balance the surface work across ranks.

## Event-location design for the spall firing (not implemented; for a /plan packet)
Facts from Removal.H / UpdateSpAfterMechanics that fix the design:
- Gate: Sp_top(i,j,k_top) >= 1 (weibull on: cluster id > 0, itself Sp >= 1 per face), Sp computed
  from the END-of-step T of the top cell (local thermoelastic sigma(T), K_I(a_f), K_Ic(T)).
  Removal runs at the start of the next Advance, before the H/T swap, so at that point temp_mf = T_new
  and temp_old_mf = T_old of the step in which the crossing happened. Both profiles are available.
- Flake: depth scan K_I(z) >= K_Ic(T(z)) on the current profile, h_col refined to dz/256; phi shifts by
  h_col/cos; voided cells keep their H frozen (ledger counts it); pin_T = T_top at firing; firing time
  stamped `time` (= end of the crossing step).
Design (switch `spall.event_location = 1`, default 0 to keep every baseline bit-identical):
1. Keep the previous step's per-column Sp_top (one ncols vector, reduced like the others).
2. On a new firing with Sp_old < 1 <= Sp_new: theta = (1 - Sp_old)/(Sp_new - Sp_old); t_fire = time -
   (1 - theta) dt. Sp is near-linear in T over one step's few K, so the crossing error is O(dt^2).
3. Column profile at t_fire by cell-wise interpolation T_theta = T_old + theta (T_new - T_old) (both
   fields exist); run the depth scan and K_Ic on T_theta so h_col is the flake at the crossing.
4. Freeze every voided cell at H_theta (= H_old + theta (H_new - H_old)); the removed top cell then
   leaves at Sp = 1, and pin_T = T_theta,top, pin_t = t_fire (the pinned closure's t_cell follows).
5. Hand the excess (1 - theta)(H_new - H_old) of each voided cell to the new surface cell of the column
   (it is the heat absorbed after the crossing); the ledger then closes exactly and no flux is lost.
6. CSV: t = t_fire, T_top = T_theta; ROP diagnostics unchanged (h_col/dt).
Then dt is limited by resolving the fresh-cell heat-up (~0.7 s at 1 mm; 10-20 steps -> ~50 ms) and by
the explicit diffusion limit (0.24 s at 1 mm). Expected ~10x fewer steps at 1 mm.
Tests: (a) unit: one-column prescribed flux, dt = 1/4/16/64 ms: fired T_top - T_crit must be << q dt/
(rho Cp dz) and shrink ~dt^2, first-firing times converge, ledger at round-off; (b) reproduction:
R7b_2mm at 4 ms with event location must match the old 1 ms fixed-step ROP within its 1 % band
(the event-located answer is the small-dt limit); (c) dt ladder 4/16/64 ms at 2 mm to set the
per-mesh fixed step.
Caveats: Sp cluster gate (A_crit) fires on the labelled set, theta is per column; mechanical
(regime 4) and vapour paths untouched; surface-normal kernel off in the campaign.

## dt ladder result (R7b_2mm, 4 → 128 ms; full table in d2c_steady/RESULTS.md)
8 and 16 ms pass the pre-stated acceptance (ROP −0.1 / −1.0 %, t_bottom +0.4 / +1.2 %, Ø within
0.5 mm). 32 ms fails (scorer ROP +4.4 %, min Ø −2.4 mm), 64 and 128 ms fail. Firing T barely moves
(pinned closure caps it); the flake thickness grows with dt (1.01 → 1.11 mm) because the depth scan
sees an overshot profile — the quantity event location fixes. Adopt 16 ms at 2 mm, 8 ms at 1 mm.
Wall: 2 mm 561 s in 12.5 min at 16 ms (was 83 min).
